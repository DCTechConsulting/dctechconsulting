Purpose & Approach
Provide business users with read-only access to the existing RDS SQL Server Enterprise read replica via SSMS, without AWS access and without per-user DB logins. Approach: use AWS Managed Microsoft AD to domain-join the RDS instance and enable Windows Authentication (Kerberos), then grant access via a single AD security group mapped to a least-privilege database role.

Conditions & Assumptions
Engine: Amazon RDS for SQL Server Enterprise; read replica/reader endpoint available.

Users: Corporate AD accounts on domain-joined Windows machines using SSMS.

Network: Private connectivity to AWS VPC (VPN/Direct Connect/Client VPN); database remains private (no public access).

Identity: Corporate AD is trusted by AWS Managed Microsoft AD (or users/groups temporarily created in AWS Managed AD).

Hygiene: Correct DNS and time sync across environments (required for Kerberos).

Access Model & User Experience
One AD security group (e.g., SQL_RO_BusinessUsers) is mapped in SQL Server to a read-only DB role with access limited to required schemas/tables/views.

No per-user SQL logins; onboarding/offboarding is managed by AD group membership only.

Users connect with SSMS using Windows Authentication to the read-replica endpoint; no AWS account or credentials needed.

Security & Operations
Enforce MFA/Conditional Access in corporate IdP; least-privilege grants (prefer views), and keep inbound 1433 restricted to known VPN/office ranges.

Enable SQL Server auditing to central logs; perform periodic access reviews of the AD group.

Validate Kerberos (time/DNS/SPNs), and ensure read-only behavior and stable access during failover.
